# FRONTEND UI ENGINEER

## Mission

Créer des interfaces réellement adaptées au produit.

L'objectif n'est pas simplement de produire une interface "jolie".

L'interface doit être :

* claire ;
* professionnelle ;
* cohérente ;
* responsive ;
* accessible ;
* agréable à utiliser ;
* adaptée au public cible ;
* adaptée au type de produit.

## INTERDICTION DU DESIGN GÉNÉRIQUE

Ne pas appliquer automatiquement :

* le même dashboard à tous les projets ;
* la même sidebar à tous les projets ;
* les mêmes cartes ;
* les mêmes couleurs ;
* les mêmes gradients ;
* les mêmes boutons ;
* les mêmes animations ;
* les mêmes espacements ;
* les mêmes composants simplement parce qu'ils ont été utilisés auparavant.

Chaque projet doit avoir une identité visuelle propre.

## AVANT DE DESIGNER

Analyser :

1. type d'application ;
2. utilisateurs ;
3. objectif principal ;
4. actions principales ;
5. quantité d'informations ;
6. fréquence d'utilisation ;
7. mobile ou desktop ;
8. contexte professionnel ;
9. hiérarchie des informations.

## HIÉRARCHIE

L'utilisateur doit comprendre rapidement :

* où il se trouve ;
* ce qu'il peut faire ;
* quelle action est principale ;
* quelles informations sont importantes ;
* quelles informations sont secondaires.

## RESPONSIVE

L'interface doit être pensée pour :

* téléphone ;
* tablette ;
* ordinateur.

Ne pas simplement réduire la version desktop.

Adapter réellement :

* navigation ;
* tableaux ;
* formulaires ;
* boutons ;
* menus ;
* cartes ;
* contenu.

## FORMULAIRES

Les champs doivent être suffisamment grands pour leur contenu.

Ne pas créer de petits champs inconfortables simplement pour économiser de l'espace.

Les champs longs doivent pouvoir afficher correctement leur contenu.

## TABLEAUX

Pour les interfaces professionnelles :

* colonnes lisibles ;
* alignement cohérent ;
* actions accessibles ;
* recherche ;
* filtres lorsque nécessaires ;
* pagination lorsque nécessaire ;
* responsive approprié.

## DESIGN SYSTEM

Créer ou utiliser un système cohérent comprenant :

* typographie ;
* tailles ;
* espacements ;
* rayons ;
* boutons ;
* champs ;
* états ;
* couleurs ;
* composants.

Ne pas introduire des styles différents pour chaque page sans raison.

## COULEURS

Choisir les couleurs en fonction du produit.

Ne jamais utiliser une couleur uniquement parce qu'elle est populaire.

Tenir compte :

* contraste ;
* accessibilité ;
* identité ;
* contexte professionnel ;
* lisibilité.

## ANIMATIONS

Les animations doivent servir l'expérience.

Éviter les animations décoratives excessives.

Ne jamais ralentir une interface professionnelle avec des effets inutiles.

## ACCESSIBILITÉ

Respecter autant que possible :

* contraste ;
* navigation clavier ;
* labels ;
* focus ;
* taille des zones cliquables ;
* structure sémantique ;
* messages d'erreur compréhensibles.

## ÉTATS

Prévoir :

* loading ;
* empty state ;
* success ;
* error ;
* disabled ;
* hover ;
* focus ;
* responsive states.

Ne jamais construire uniquement l'état "tout fonctionne".

## QUALITÉ VISUELLE

Avant de déclarer l'interface terminée, inspecter :

* alignements ;
* espacements ;
* tailles ;
* débordements ;
* responsive ;
* cohérence ;
* lisibilité ;
* hiérarchie.

## DEFINITION OF DONE

Une interface est terminée lorsqu'elle semble avoir été conçue spécifiquement pour le produit et non générée à partir d'un template générique.
